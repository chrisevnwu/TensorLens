# Contributing to TensorLens

A lab starts with a claim a reader can test. The numerical engine implements the claim, Vitest checks it, and the workbench exposes the same numbers for inspection. Before starting, read the engineering rules and the product, architecture and lab specifications. Check the roadmap and progress log for work already in flight. [Engineering protocol](AGENTS.md) · [Product](docs/PRD.md) · [Architecture](docs/ARCHITECTURE.md) · [Lab specifications](docs/LAB_SPECS.md) · [Roadmap](ROADMAP.md) · [Progress](PROGRESS.md)

## Set up the checkout

From the repository root, use Node.js 24 with npm.

```sh
npm ci
npx playwright install chromium firefox webkit
npm run dev
```

Vite prints the development URL. The production browser tests start their own preview on port 4174. On a clean Linux CI runner, install the browsers and system packages with `npx playwright install --with-deps chromium firefox webkit`.

## Add a lab

### 1. Specify the model and its experiments

Choose a stable kebab-case ID and an existing chapter. Define the inputs, dimensions, valid ranges, formulas and units in the lab specification. Identify a small case you can solve by hand, a limiting case and a failure mode. Describe the presets and three challenges in terms of observable quantities or interactions. Write down any approximation underlying a metric such as memory, FLOPs or elapsed time.

For example, a proposed `vector-centering` lab could let a reader shift every input by the same constant. Centering subtracts the mean, so that shift cancels. Translation invariance, the zero sum of the output and a constant-vector input give three independent starting points for tests.

### 2. Get the pure engine green

Create `src/engine/labs/vector-centering/__tests__/engine.test.ts`. Start with an independently calculated oracle, then implement the public simulation in `src/engine/labs/vector-centering/engine.ts`. Keep the configuration and result types explicit. Return intermediate states when a learner needs to step through the calculation. A preset stores input values and a stable ID. Its displayed name belongs in the dictionary.

Use the shared matrix, PRNG and numerical utilities when applicable. Keep React, DOM access and browser state outside the engine. Guard the algorithm's declared domain, handle degenerate inputs and test the extremes exposed by the controls. For a stochastic lab, check that replaying a seed reproduces the numerical trace. Exercise the real presets to prove that the challenge targets can be reached. [Math primitives](src/engine/math/) · [Example engine and tests](src/engine/labs/embeddings-rope/)

```sh
npx vitest run --project engine src/engine/labs/vector-centering
npm run test
```

Run the full Vitest suite successfully before writing the interactive canvas, challenge components or bilingual copy.

### 3. Implement the workbench and typed copy

Default-export a page from `src/labs/vector-centering/index.tsx`. Put its bilingual strings in `src/i18n/labs/vector-centering.ts`. A missing translation must fail the typecheck.

```ts
import type { ExactStringTree } from '../types'

const en = {
  presets: { offset: 'Shift all coordinates' },
  shift: 'Input shift',
  centeredSum: 'Sum after centering',
} as const

const zh: ExactStringTree<typeof en> = {
  presets: { offset: '平移所有坐标' },
  shift: '输入平移量',
  centeredSum: '中心化后的总和',
}

export const centeringCopy = { en, zh }
```

Use `centeringCopy[useI18n().locale]` inside the page. Translate control labels, units that require words, error states, canvas descriptions, presets and challenge insights. Give numeric inputs accessible names and offer a keyboard alternative to pointer interactions.

Use `ExperimentShell` for the shared `LabShell`, playback and keyboard shortcuts. Supply `labId`, `step`, `maxStep`, `onStepChange`, `onReset`, presets, controls, the computed stage, metrics, inspector, explainer and challenge list. Each challenge supplies a stable `id`, translated `title`, `description`, `insight` and a boolean `completed` derived from the experiment. The shell persists completed IDs. Reuse `FormulaBar`, charts and controls where they fit. Derive the SVG or Canvas rendering from the engine output and use semantic theme colors. [Workbench contract](src/components/layout/ExperimentShell.tsx) · [Visualization primitives](src/components/viz/) · [Theme tokens](src/styles/tokens.css)

Define module-level defaults and a typed URL codec with `makeUrlCodec` and `useLabUrlState`. Decode the named preset first, restore its overrides and bound dependent selections such as a row index after a shape change. Include the step, editable inputs, selected item and any seed or observation state that changes the experiment. Preserve floating-point precision where a value is generated by the engine. Pass `getShareUrl` to the shell so sharing uses the current state even during a control change. [URL helpers](src/components/utils/useLabUrlState.ts) · [Working lab example](src/labs/attention-debugger/index.tsx)

### 4. Register the lazy page and presets

Append a `LabDefinition` to `LAB_REGISTRY` in `src/labs/registry.ts`. The registry imports React's `lazy` and provides the `text` and `tags` helpers. For example, after the current 18 labs the next entry would look like this.

```ts
{
  id: 'vector-centering',
  number: 19,
  chapter: 'architecture-inference',
  difficulty: 'foundational',
  title: text('Vector Centering', '向量中心化'),
  description: text('Shift a vector and inspect its centered coordinates.', '平移向量，查看中心化后的坐标。'),
  tags: tags(['Centering', '中心化'], ['Mean', '均值']),
  component: lazy(() => import('./vector-centering')),
}
```

The hash route `#/labs/vector-centering`, catalog, chapter filtering and neighbor links use this registry. Add the lab's schematic to `LabPreviewIcon`. In `src/labs/presetCatalog.ts`, import `centeringCopy` and add `'vector-centering': centeringCopy` to the `dictionaries` record. Its `presets` keys must match the IDs understood by the URL codec. The palette can then navigate to `#/labs/vector-centering?preset=offset` without importing the simulation. Update the English and Chinese lab tables together. [SDK types](src/labs/types.ts) · [Registry](src/labs/registry.ts) · [Catalog schematics](src/components/viz/LabPreviewIcon.tsx)

### 5. Verify the public route

Add a focused Playwright test under `e2e/` using the shared fixture. Drive an actual control, check an independently expected metric, exercise a challenge and reload a shared URL. The registry-driven browser checks cover exported PNGs and restored playback. Exercise both languages and themes on desktop and mobile, and keep the console and page free of errors and horizontal overflow. [E2E fixture](e2e/fixture.ts) · [Registry-driven tests](e2e/labs.spec.ts)

Run the complete gate from the repository root. The build produces the `dist/` directory used by Playwright.

```sh
npm run typecheck && npm run lint && npm run test && npm run build && npm run test:e2e
```

Review the build output for the new lazy lab chunk and the initial landing payload. For a milestone, check off its roadmap items and record the observed test counts and bundle size in the progress log **after** all five checks pass. Commit the coherent change and describe the mathematical result and how to reproduce it in the pull request.
